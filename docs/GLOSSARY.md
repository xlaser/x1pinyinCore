# 词汇表

代码注释与测试中使用的领域术语速查。候选"颜色"体系来自宿主候选窗的着色
传统，引擎内部对应 `Candidate` 的标志位。

## 候选类型（颜色体系）

| 术语 | 标志位 | 含义 |
|---|---|---|
| 白词 | —（普通候选） | 来自词库/用户词表的普通词条 |
| 绿词 | `is_sentence` | 整句/自组词候选：DP 拼出的完整句或用户自造词记忆（如输入整句后再次输入时整句直出） |
| 紫词 | `is_guess` | 长词延展猜测：输入是更长词的拼音前缀时，更长词作为猜测候选进入（如 `hupeng` →「狐朋狗友」） |
| 橙词 | `is_correction` | 纠错候选：识别为误触/拼错的输入经变形规则还原后的候选 |
| 英文候选 | `is_english` | 英文补全/混输候选（独立英文词表） |

## 输入形态

- **全拼**：完整拼音串（`nihao`）
- **简拼**：每字母一个字的声母首字母（`nh` → 你好），支持混合
 （`jhpy` 拼音里 `py` 补全）
- **简拼整词**：候选字数恰好等于输入字母数、每字母对一字（`ssef` →
  似是而非）——最强对位结构证据，排序置于顶层
- **双拼**：声母+韵母双键编码，8 套内置方案 + 自定义方案 JSON
- **零声母**：a/e/o 等无辅音起始的音节（含 y/w 拼写约定）

## 学习体系

- **commit**：用户上屏一个候选，触发学习（词频、拆词、关联、映射）
- **拆词学习**：整句上屏后按最优切分子词分别累计频率与词间关联
- **固化（solidify）**：整句记忆转为正式用户词（白词）；普通数字键上屏
  只拆词，Shift+数字键强制固化
- **绿词记忆（green_memo）**：会话级整句缓存，重启后靠关联举一反三重建
- **固定候选（pins）**：用户把某输入钉死在 1-3 号位（候选窗 Ctrl+数字），
  免疫一切排序调整
- **输入映射（input_mappings）**：原始按键串 → 上屏文本的历史映射加分
- **bigram / trigram**：二/三阶上下文共现模型（词级，带时间衰减）
- **collocation**：词库权威搭配（上文字 + 候选拼成词库词 → 硬规则优先）
- **竞争退化通道**：词的权重不由绝对使用次数决定，而由同音/同场景竞争
  中的选择分布决定——长期竞争失败者退化让位（`competition.rs`）
- **主音 / 次音**：多音字的最常用读音（如「地」主音 de）与其他读音；
  精确匹配同分组内主音优先，用户偏好可反超

## 引擎机制

- **音节图 DP**：把切分候选组织成有向无环图，动态规划找最优/次优路径
 （整句解码核心）
- **N-best**：DP 保留的前 N 条路径（绿词生成的候选池）
- **双向词格重打分（backward）**：前向 DP 只看左上文；上屏前用右文
 （后向 bigram）对 N-best 二次打分（「认真地考虑 vs 认真的考虑」由右文裁决）
- **同音歧义槽（ambiguity）**：同音异形整句的判定与上下文证据分
- **弱搭配惩罚**：整句切分中相邻段无搭配证据时的分数惩罚（防垃圾切分）
- **双写折叠（双击故障）**：快速连击同键产生的重复字母按击键间隔门控
 折叠纠错（`process_timed`，时序感知）
- **键预计算排序**：排序键每候选算一次再元组排序，替代比较器内重复查询
- **参考比较器**：逐对比较的完整语义实现，与生产键排序由等价性测试互证

## 存储

- **内置词库**：编译进二进制的单字表（约 3000 条，开箱兜底）
- **种子 DB**：完整词库 SQLite 文件（词库资产本体，见 [DICT.md](DICT.md)）
- **双库分离**：`dict.db`（词库，可被种子覆盖）+ `user.db`（用户数据，
  永不触碰）的宿主可选布局
- **sync_hash**：词库内容哈希，用户库启动比对触发增量同步
- **flush**：内存学习态定期批量落盘（写成功才清 pending，失败回填重试）
- **空态覆写闸**：启动加载失败时禁止用空内存态覆写用户表的保护
