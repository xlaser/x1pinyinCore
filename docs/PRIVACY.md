# 隐私说明

## 总则

x1core 是**零网络**引擎库：不依赖任何网络组件（依赖树中无网络 crate），
不采集、不上传任何数据。所有用户数据只写本机 SQLite 文件。

但请如实知悉：**本地数据是明文的**。本文列出引擎在本机存储的全部内容
与清除方式。

## 本地明文存储清单

以下表全部位于用户库（单库布局的 `x1pinyin.db`，或双库布局的 `user.db`）：

| 数据 | 表 | 说明 |
|---|---|---|
| 用户词条 | `user_words` | 上屏固化的词/自造词（含拼音与频次） |
| 输入映射 | `user_input_mappings` | **原始按键串 → 上屏文本**的映射与次数 |
| 二阶共现 | `user_bigram_counts` | 上屏词与词的相邻序列（带次数） |
| 三阶共现 | `user_trigram_counts` | 上屏词三元组序列 |
| 词条计数 | `user_counts` / `user_pinyin_counts` | 词条与 (词,拼音) 的选择次数 |
| 删除黑名单 | `user_blacklist` | 用户删过的词（防复活） |
| 固定候选 | `user_pins` | 钉死的候选位 |
| 竞争统计 | `competition` / `competition_totals` | 同音竞争的选择分布 |
| 上下文快照 | `db_meta.context_snapshot` | 最近上屏词序列（重启恢复上下文） |
| 英文计数 | `user_english_counts` | 英文词条选择次数 |

**上述数据组合起来足以重建用户的打字历史。** 任何能读取这些文件的人
（同机其他权限足够的进程/用户、物理接触者、备份同步目标）都能获得该信息。

可选模块（默认关闭，宿主显式启用才存在）：

- **输入统计**（`x1_stats_init` 启用）：独立的 `x1stats.db`，记录每日字数、
  上屏次数、热字热词等聚合统计；
- **panic 日志**：引擎崩溃时写文件日志（路径由宿主经 `X1_PANIC_LOG`
  指定），panic 消息可能包含触发输入的片段。

宿主前端可能另有自己的本地产物（如选词日志），不在本库范围内，请查阅
所用输入法发行包的说明。

## 清除方式

**粒度清除**（经 FFI，由宿主界面触发）：

- `x1_engine_clear_user_words` — 清空用户词条
- `x1_engine_clear_input_mappings` — 清空输入映射
- `x1_engine_clear_context` — 清空当前上下文栈
- 删词（`x1_engine_remove`）— 移除词条并加入黑名单（防复活）

**彻底清除** = 删除用户库文件本身：

- 双库布局：删除 `user.db`（`dict.db` 为词库，不受影响）；
- 单库布局：删除 `x1pinyin.db` 会连同词库一起清掉（引擎会回退内置单字表，
  放回种子可恢复词库）。

> 已知限制：当前没有"一键清除全部学习数据"的单一 FFI 入口（需宿主逐项
> 调用或直接删库文件）。单一入口在路线图上。

## 建议给发行包打包者

- 在产品说明中告知用户数据位置与上述清除方式；
- 卸载流程明确"是否保留学习数据"的选项（默认保留还是清除由产品定，
  但应可发现）；
- panic 日志设置轮转或体积上限，避免无限增长。
